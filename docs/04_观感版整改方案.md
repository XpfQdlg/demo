版本：2026-11-05
前置文档：`03_联动指挥方案.md`
定位：本文只记录「观感版与联动指挥演示走偏之后，怎么拉回来」。改代码前先读本文。

## 一、方向校正：这项目的主语是机器狗和机器人，不是场景

### 1.1 走偏在哪

`03` 定的是：3D 主画面是**第一人称的机器视角**，九个执行体是展示主体，
场景是它们活动的场地。观感版（`cinematic.html`）做成了一条独立支线：
自由轨道相机、没有执行体视角、机器人只是场景里两个会走的小模型。

用户的原话是「视角为什么不是机器人和机器狗的主体了，我是让你重构建模不是让你重新做」。
意思很清楚：要的是**把原来的模型重建得更真**，不是另起一个看风景的预览页。

### 1.2 结论

观感版的材质与场景构件（PBR 材质、建筑构件、地形、站台）是有效资产，
但它必须回到 `联动指挥演示` 的框架里来，成为第一人称镜头看到的世界。

推荐路线，按代价从小到大：

| 方案 | 做法 | 代价 | 结论 |
| --- | --- | --- | --- |
| A | 观感版加「设备跟随」相机，默认跟机器狗/人形 | 半天 | 只解决看见，两个页面仍是两套 |
| B | 把观感版的场景构建接到主演示，`build_scene` 换成观感版构件，材质与光照沿用主演示 | 2~3 天 | **推荐** |
| C | 双页面并存，主演示保留旧模型 | 1 天 | 不解决割裂 |

方案 B 的边界：只换渲染资产，不动事件层、调度层、界面。
`engine.js` 的渲染器换成 `cinematic.js` 的那一套（AgX、PMREM、后处理），
`map/build_scene.js` 里四个场景的构建函数换成 `src/cine/scene_*.js`，
执行体、告警、调度、指挥图全部保持原样。

### 1.3 验收口径

主画面必须是第一人称机器视角，镜头里能看见自己走过的路、路口、楼，
切换执行体时场景跟着换。不允许出现「只有在独立页面才能看到新模型」。

## 二、小区位置：东南角那几栋楼就是小区

### 2.1 现象

校园场景东南侧多出一片成排的楼，其中一栋跑到了校园里面；
「小区」页签里的七栋楼与真实小区对不上。

### 2.2 根因

`expand_community.py` 把小区轮廓扩到了 19707 平方米（横跨 x 709~1064），
`enrich_community.py` 在这个范围内重新摆楼，摆出了一栋中心在 x ≈ 816 的楼，
落进了校园用地。真实的小区是校园东南角那一组，范围约 x 875~1010、y 1040~1200。

### 2.3 改法

1. `enrich_community.py` 增加硬约束：楼栋中心必须落在 x ≥ 875 的像素范围内，
   任何越界的候选直接丢弃，不参与摆放。
2. 小区轮廓不再向西北扩，改成围绕东南那组楼向外扩一圈，
   东西向不超过 x = 1010（校园东边界附近）。
3. 校园场景里 `add_community()` 只摆楼、路、围墙，不再生成远处的成片体量，
   避免和 `add_distant_town()` 叠在同一片地方。
4. 已有 7 栋重新生成后，逐栋与卫星图核对，越界的全部删除。

### 2.4 实际做法（2026-11-06）

对照标注图复核后，方案收敛为「回退到描图轮廓」，比上面的改法更彻底：

1. `expand_community.py` 不再扩边，改为把 `zones.community` 恢复成描图阶段的原始品红圈，
   即 x 799~1007、y 1048~1255，7746 平方米。此前的 19707 平方米是扩错了。
2. `enrich_community.py` 把数据包里已有的人才公寓当作硬障碍，摆程序楼时避让；
   结果可建区已被真实楼占满，程序楼生成 0 栋——这才是对的，小区原本就只该有那几栋。
3. `scene_community.js` 新增 `package_buildings_in_zone()`，小区页签直接画数据包里的真实楼；
   校园场景传 `packageBuildings: false`，避免同一栋画两遍。
4. 并集楼 `talent_apartment` 与 `p2`~`p6` 重复，已删除并集那条。

### 2.5 小区与校园连通（2026-11-06 第二轮）

第一轮只是把范围改对，小区在画面上仍像一块被围墙圈起来的飞地。按用户要求改为真正连通：

1. **小区页签不再单独建场景**。`BUILDERS.community` 直接用 `build_campus`，
   小区机位由 `VIEWS.community` 的 `center`/`span` 指定。
   两个页签共用同一棵场景根节点，来回切只重设机位，不重建（重建一次要几秒）。
   快速路径靠 `SAME_SCENE` 判断，卸载时按保存的根节点删，不按页签名找。
2. **连接道**：`closest_pair()` 求小区轮廓与校园轮廓最近的一对点，铺一条 9 米宽的铺装道，
   两端各向两侧延伸 8 米接进地面。
3. **围墙断开**：接口 45 米内的顶点不拉栏杆，栏杆按连续段分开生成，
   原来是一整圈闭合折线。

### 2.6 工作量

半天。改两个脚本的约束，重跑两次数据，重看截图。

## 三、地铁镜头能穿出站厅

### 3.1 现象

在地铁场景里拖动或滚轮，相机可以退到站厅墙外，看到盒子外面的天空和地块边缘。

### 3.2 根因

`cinematic.js` 的轨道相机没有任何空间约束，`distance` 上限 260 米，
而站厅只有 185 × 47 米。相机沿水平方向退到 92 米之外就出去了。

### 3.3 改法

在 `Cinematic` 里加一个可选的相机包围盒 `cam_clamp`，由场景自己声明：

```js
// scene_subway.js 里
cine.cam_clamp = {
  x: [cx - 88, cx + 88],
  y: [1.0, 5.4],
  z: [cz - 19, cz + 19],
};
```

每帧算完相机位置后，把 `camera.position` 夹进盒子里，同时把
`orbit_target` 也夹进去，避免相机贴墙了目标点还在墙外导致画面全是墙。
`bind_orbit()` 里按下新的场景时清空上一个场景的 `cam_clamp`。

### 3.4 实现（2026-11-06）

1. `Cinematic._loop()` 里算完相机位置后夹进 `cam_clamp`，目标点同时夹，
   否则相机贴墙时 `lookAt` 还盯着墙外，画面全是一堵墙。
2. `bind_orbit()` 开头把 `cam_clamp` 清空，切场景时不会沿用上一个场景的盒子。
3. 包围盒由场景在 `root.userData.frame.cam_clamp` 里声明，
   `cinematic_main.js` 的 `frame_object()` 在 `bind_orbit` 之后写回 `cine.cam_clamp`。
4. 地铁的盒子按站厅实测尺寸算，不写死数字：
   `x` 取厅宽两端各留 4 米，`z` 取厅深两端各留 4 米，`y` 取 1.0 到净高减 0.6 米。

验收：把距离拉到 240~260 米、仰角拉到 0.9，相机仍在站厅内，看不到盒子外的天空与地块边缘。

### 3.5 工作量

半天。改动集中在 `cinematic.js` 一处，`scene_subway.js` 声明一个包围盒。

## 四、西北方向还有连起来的楼

### 4.1 现象

校园西北角的 `north_dorm_*`、`west_dorm_*` 在 3D 里连成一堵两三百米的墙。

### 4.2 根因

`split_long_buildings.py` 已经把长楼按 45 米切开（52 栋变 65 栋），
但切出来的相邻段是**共边**的。观感版用 `shrink: 0.8` 从质心等比缩小，
每段只让出不到一米，远看仍然是一条连续的墙。

实测：`north_dorm_s1` 与 `s2`、`s3`、`s4` 的间距都是 0.0 米，
`west_dorm_s1~s5` 同样是 0.0 米。

### 4.3 改法

只对切出来的段（id 形如 `xxx_s数字`）加大收缩量，独立楼不收缩：

```js
shrink: /_s\d+$/.test(b.id) ? 2.6 : 0,
```

按质心等比缩 2.6 米，相邻两段之间就会有约 5 米的山墙间距，
既保留原来的体量关系，又能一眼看出是几栋楼。
同时把切分脚本的 `TARGET_LEN` 从 45 米调成 36 米，条数变多、每段更短，更接近真实板楼。

### 4.4 实现（2026-11-06）

1. `split_long_buildings.py` 改成可重跑：开跑前先把上一轮切出的 `xxx_sN` 按栅格求并回一整块，
   再按新长度重切。否则改一次长度就多切一刀，编号还会套成 `_s1_s1`。
2. `TARGET_LEN` 45 → 36 米；**主教学楼 `teaching_1` 不切**（东西向一整栋，是校园主轴），
   建筑总数 65 → 64，其中切出来的段 18 条。
3. `scene_campus.js` 的收缩量改为按 id 判断，且每段略有差别（2.2~3.2 米），
   独立楼不收缩。相邻段让出五到七米，远看是几栋楼而不是一堵墙。
4. 切点各抖 ±3 米，段与段长短不一致；隔一段错一层高（+3 米），
   屋顶不再四平齐顶。

### 4.5 工作量

半天。改两个数字，重跑一次切分与截图。

## 五、西南角水库两侧没有建筑

### 5.1 现象

校园西南角的水面（`water_south`，约 56 × 102 米）两侧是空地。

### 5.2 事实（2026-11-06 更正）

原先的判断是错的：水库两侧**实际上没有建筑**。

早先看到数据包里有 `reserved_sw`、`reserved_sc` 两块，就按「实心色块」把它们抬到 14 米、
换成外墙材质。做完之后对照卫星图复核，水库两侧是空地与绿化，这两块是描图时
把邻近地块的填色误当成楼体，属于假数据。抬高度只是把两块凭空长出来的楼做得更像楼。

正确做法是删掉，不是修好。

### 5.3 改法

1. 删除 `reserved_sw`、`reserved_sc`，不再参与渲染与寻路的建筑掩膜。
2. 水库岸线由长直线改成分形噪声位移后的自然曲线，位移只向内（0~2.5 米），
   不会啃到岸边道路。
3. 森林边界由 98 × 140 米的矩形改成内切椭圆加半径噪声的团块，落在原矩形之内。
4. 按新轮廓重绘 `ground.png`（只有校园灰 / 森林绿 / 地铁深灰三种纯色填充）。

脚本：`map_trace/newmap2/reshape_terrain.py`。原始轮廓存在 `_reshape_src.json`，
可重复运行，不会因为跑第二遍越缩越小。

### 5.4 顺带剔除的重复楼体

东南角的人才公寓在数据里有 6 条：一条 `talent_apartment` 是并集轮廓（1991 平方米），
另有 `p2`~`p6` 五条单栋（合计 1437 平方米）。并集与单栋叠在一起画，
在 3D 里就是几栋楼彼此穿插。已把并集那条一并列入剔除清单，只保留单栋。

## 八、设备跟随（方案 A 首步，2026-11-06）

观感版的场景资产到位之后，先补上「镜头跟着设备」这一层。这一步不是支线，
它的相机逻辑就是方案 B 并入主演示时要复用的那一份。

| 项 | 做法 |
| --- | --- |
| 跟随相机 | `Cinematic.set_follow(entity, {mode, eye_y})`，与轨道相机互斥 |
| 第三人称 | 机位在设备后上方 5.2 米、抬 2.2 米，看向机头前方 2 米 |
| 第一人称 | 相机抬高到视高（狗 1.15 米、人形 1.62 米），机身前移 0.22 米 |
| 小窗 | 右上角 336 × 189，第二渲染器画同一棵场景，机身临时隐藏 |
| 按键 | `1–9` 跟随对应设备，`G` / `Esc` 回全局，`空格` 开关小窗，`R` 复位 |
| 默认机位 | 3D 俯视（仰角 1.02 弧度约 58°），把总平面横过来对准 16:9，代替 2D 指挥图 |

小窗为什么另起一个渲染器：主渲染器带后期管线（AO、SMAA、调色），
用视口裁切在同一个渲染器里画第二视角会破坏整条后期链；场景已经合并到二三十个网格，
再画一遍的代价可以接受。小窗渲染器关掉 `shadowMap.enabled`，阴影贴图由主渲染器维护。

### 9.2 顺带修掉的问题

**屋顶设备悬空**。`add_roof_clutter` 按包围盒撒机组与检修走道，
异形屋面（L 形、切过的段）会让机组和走道落在屋面之外，远处看是一排悬空的细条。
现在传入楼体轮廓，逐件做点在多边形内判定，屋面外的直接跳过。

### 9.3 验收方式

- `tools/checks/_probe_conn.mjs`：北区与西侧公寓各一张，看段与段之间有没有山墙缝
- `tools/checks/_closeup.mjs`：拉近看水库岸线、小区楼群
- `tools/checks/_smoke.mjs`：主演示用 `domcontentloaded` 加固定等待，确认地图改完还能建起来
  （`shot.mjs` 用 `networkidle2`，遇到长任务会一直等不到空闲，超时退出）

截图存于 `command_demo/shots/`：`conn_north`、`conn_west`、`water_shape`、
`water_shore`、`final_community`、`comm_close`、`smoke_main`。

### 9.4 数据可重复性

`map_package.json` 是生成物，也是各脚本的活工作文件。目前改它的脚本按顺序是：

```text
build_map_package.py → build_roads.py → split_long_buildings.py
→ expand_community.py → enrich_community.py → reshape_terrain.py
→ fix_road_conflict.py
```

每次改完楼体都要重跑 `fix_road_conflict.py`；改完轮廓要重跑 `reshape_terrain.py` 重绘地面。
`ground.png` 与 `scene_extra.json` 也属于生成物，不要手改。
