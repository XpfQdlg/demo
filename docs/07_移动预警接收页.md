# 移动端预警接收页

版本：2026-11-09
前置文档：`03_联动指挥方案.md`、`06_3D技术架构.md`
入口：`command_demo/mobile.html`（短地址 `/phone`）

---

## 一、这是什么

展台大屏是 3D 校园指挥中心，摄像头发现明火、人员聚集、垃圾堆积后，
监控层会自动派最近的机器狗或人形机器人前往处置。

手机端预警接收页是它的**伴随页面**：同一局域网下用手机扫码打开，
大屏上的每一步（发现 → 派单 → 到场 → 处置 → 完成）都会实时推到手机，
讲解员不用凑到大屏前也能看到异常信息。

页面同时承担「四模型场景应用」的展示：四个场景各有一个专属模型
（校园巡检 / 小区安防 / 地铁客运 / 森林火险），每条预警都带模型署名、
置信度与研判理由，右上角「模型」可以打开四模型应用总览。
模型口径与讲解话术见 `08_四大模型场景应用.md`。

手机还是**观众参与的入口**：底部「我要参与」→ 拍照 → 四模型会诊 →
一键上报 → 大屏切场景真出警、自动跟随 → 手机收到「观众上报」预警与处置回执。
流程、协议与更大胆的设想见 `09_观众参与与大胆设想.md`。

不是真实产品，是展台演示的一环：数据为模拟，不声称已接入真实监控系统。

## 二、怎么用

### 展台推荐：开发服 + 手机扫码

```bash
cd command_demo
npm install        # 第一次
npm run dev        # 监听 0.0.0.0:5179
```

1. 电脑打开 `http://localhost:5179/cinematic.html?scene=campus`（或直接 `/`）。
2. 点大屏右上角 **「手机」**，弹出二维码与局域网地址，例如 `http://10.105.1.210:5179/phone`。
3. 手机与电脑连**同一个 Wi-Fi**，扫码打开 `/phone`（302 到 `mobile.html`）。
4. 手机顶栏显示 **「实时接收」** 即接通。大屏上出现报警时，手机会同步新增卡片，
   并伴随提示音（首次触摸后解锁）与振动。

手机页也支持多台手机同时看：总线是广播的，后打开的手机会按事件日志回放补齐当前状态。

### 用构建产物演示

```bash
npm run build
npm run preview     # 同样监听 0.0.0.0:5179，总线在 preview 里也生效
```

### 单文件离线包

`观感版演示.html` 双击即开，本身没有服务，手机连不上它。两条路：

- 需要**实时**接收：展台电脑上仍跑一个 `npm run dev`（只为了预警页与总线），
  单文件大屏页会把事件发到 `http://127.0.0.1:5179/api/alerts`
  （见 `src/core/alert_publish.js`），手机扫码后一样能看。
- 只演示手机界面：手机打开任何一个能访问到 `mobile.html` 的静态服务即可；
  连不上总线时页面自动进入**演示模式**，用内置数据模拟完整预警流程，
  顶部会明确标注「演示模式」，不会冒充真实数据。
  演示模式会按 校园 → 小区 → 地铁 → 森林 **自动轮换四个场景模型**，
  每个场景报两起，观众不用碰大屏也能把四个模型各看一遍。

其他参数：

- `?bus=http://<ip>:<port>`：让页面指向另一台机器上的总线（单文件 + 独立小服务时用）。
- 声音开关状态存在 `localStorage`，刷新不丢。

## 三、数据链路

```text
cine/monitor.js                 报警状态机（发现/派单/到场/处置/完成）
  └─ cinematic_main.js 回调      组装事件
       └─ core/alert_publish.js  按契约 POST，串行发送保证顺序
            └─ tools/alert_bus.mjs   Vite 插件里的内存事件日志（最近 500 条）
                 ├─ GET /api/alerts/stream    SSE：先 snapshot，再 update
                 └─ GET /api/alerts/snapshot  事件日志（调试/兜底）
                      └─ src/mobile/store.js   回放事件、合并成卡片、持久化
                           └─ src/mobile/main.js + ui.css   列表 / 详情 / 提醒
```

**为什么走开发服里的总线**：手机与电脑是两个页面实例，`BroadcastChannel`
出不了本机；展台也没有后端。Vite 插件是现成的本机 HTTP 服务，加一小块
内存中转即可，不引入任何新进程与依赖。

**为什么快照就是事件日志**：事件本身就是状态机。新手机连上后按顺序回放
最近的事件就能得到完整列表，服务端不需要再维护一份「当前状态」，
断线重连、刷新页面、后打开的手机走的是同一条恢复路径。

### 事件契约（v1）

定义在 `src/mobile/contract.js`，大屏与手机端共用。

```json
{
  "v": 1,
  "type": "alarm | dispatched | arrive | handling | resolved | scene",
  "scene": "campus",
  "scene_label": "校园",
  "incident": {
    "id": "campus-1-xxx",
    "kind": "fire | crowd | trash",
    "name": "明火",
    "area": "教学区 12东侧",
    "camera": "cam-1",
    "px": [421, 318],
    "level": 3,
    "scene": "campus",
    "scene_label": "校园",
    "analysis": {
      "confidence": 0.93,
      "detect": "cam-1 视觉检测",
      "rationale": "教学区 12东侧画面出现明火并伴随烟雾扩散，判定为需立即处置的消防风险。",
      "suggestion": "就近调度执行体到场处置，同步通知安保并按消防预案升级。"
    }
  },
  "agent": { "name": "dog-2", "type": "dog" },
  "distance_m": 28,
  "eta_s": 19,
  "note": "cam-1 自动识别，已进入就近调度",
  "source": "cinematic",
  "ts": 1794156311354
}
```

- `incident.id` 在整条生命周期内不变，手机端按 id 合并成一张卡片。
  大屏每轮会重建 incident 对象，id 用 `WeakMap` 挂在对象上（见 `alert_publish.js`）。
- 状态机只允许前进（phase 递增），网络抖动导致的乱序事件不会让卡片倒退。
- 切页签会发一条 `scene` 事件，手机端把旧场景没闭环的预警收尾，
  避免永远挂在「处置中」。
- `incident.analysis` 是模型输出层：真实模型接进来前由
  `contract.js` 的 `default_analysis()` 生成稳定的模拟值；接真实模型后
  按同名字段覆盖即可，手机端不用改。
- 场景到模型的映射在 `contract.js` 的 `SCENE_MODELS`（校园巡检 / 小区安防 /
  地铁客运 / 森林火险），大屏模型条与手机端共用这一份。

## 四、手机页功能

| 模块 | 说明 |
| --- | --- |
| 顶栏 | 连接状态（实时接收 / 连接中 / 重连中 / 演示模式）、未读角标、声音开关 |
| 场景条 | 当前大屏场景、监控点位数量、最近更新时间 |
| 统计条 | 待处置 / 处置中 / 已处置 / 今日 |
| 筛选 | 全部 / 待处置 / 处置中 / 已处置，纯前端切换 |
| 预警卡片 | 类型图标、区域、模型署名与置信度、等级、摄像头、时间、状态说明、五段处置进度 |
| 详情抽屉 | 四模型接入 chips、应用链路（识别→研判→调度→触达）、模型研判（置信度/理由/建议）、生命周期时间线、处置设备、距离与 ETA |
| 模型总览 | 顶栏「模型」按钮：4 张模型卡（能力、覆盖范围、演示接入的异常类型、今日预警数）+ 应用链路说明 |
| 提醒 | 新预警 toast、提示音（WebAudio，首次触摸解锁）、振动、未读红点 |
| 观众参与 | 底部 CTA：拍照/演示照片 → 四模型会诊动画 → 一键上报指挥中心 → 观众上报徽标与处置回执 |
| AEGIS 四 Tab | 预警 / 模型 / 参与 / 我的；参与页含拍照、语音、巡检点、盲盒与本场战报；我的页含角色、积分、榜单与连接设置 |
| 现场回传 | 观众上报详情里显示机器狗第一视角帧（大屏跟随出警时推送） |
| 兜底 | 断线保留列表并自动重连；连不上总线自动进演示模式；刷新后恢复上次列表 |

`prefers-reduced-motion` 下关闭所有动画；适配 iPhone 安全区；
390 × 844 为主要验收视口，桌面宽度下居中呈现。

## 六、验收

先起 dev server，再：

```bash
cd command_demo
node tools/checks/_alert_bus_probe.mjs            # 大屏五段生命周期是否都推到总线
node tools/checks/_e2e_phone_probe.mjs            # 端到端：大屏报警 → 手机收到 → 处置闭环
node tools/checks/_mobile_probe.mjs               # 手机页：实时链路 + 演示模式 + 交互
node tools/checks/_phone_link_probe.mjs           # 大屏「手机」二维码与局域网地址
node tools/checks/_model_bar_probe.mjs            # 四模型场景应用：大屏模型条与场景本地化
node tools/checks/_visitor_bus_probe.mjs          # 观众上报总线协议（含大屏离线兜底）
node tools/checks/_visitor_probe.mjs              # 观众上报端到端：手机上报 → 大屏出警 → 手机回执
node tools/checks/_phone_v3_probe.mjs             # AEGIS 四 Tab + 语音/AR/盲盒/我的/现场回传
node tools/checks/_bigscreen_session_probe.mjs    # 大屏在线值班员/本场战报/语音指挥/回传帧
```

## 七、边界与已知问题

1. **必须同一局域网**。二维码里取的是本机第一个非回环 IPv4；多网卡机器
   （有线 + Wi-Fi）可能取到手机连不上的那个，此时手动在手机输入
   `http://<电脑局域网IP>:5179/phone`。
2. **总线在内存里**。dev server 重启后事件日志清空，手机端会因快照清空列表；
   这是预期行为，展台开演前重启一下服务即可。
3. **没有鉴权**。展台内网使用，接口只监听本机起的开发服，不要暴露到公网。
4. **手机以接收为主，但可参与上报**。派单与处置仍由大屏自动调度完成；
   手机可以拍照/语音/巡检上报触发真实出警（观众上报闭环），也能在详情里看回传帧。
   如果以后要加「手机确认收到」「转人工」，在总线上加一条写接口即可，
   事件契约已经留了 `note` 与自定义字段的空间。
5. **演示模式不是真实数据**。顶部会明确标注；讲解时不要把它说成现场画面。
6. **单文件离线包要实时接收，需要另起 dev server**（见 §2）。
   如果现场不允许起服务，就只能给手机看演示模式的界面。

## 八、可以继续做的

- 手机确认/回执：手机点「已知晓」推回总线，大屏事件流里显示谁确认过。
- 现场截图/视频：事件里带 `media` 字段，手机详情页直接看报警截图
  （大屏已有 `src/views/video.js` 的降级接口）。
- 多场景总览：现在手机跟随大屏当前页签，以后可以在手机上并排看四个场景。
- 换真实后端：把 `alert_bus.mjs` 换成 WebSocket/HTTP 服务即可，
  事件契约与手机端 store 不用改。
