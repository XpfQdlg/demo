## 一、背景

用户提出 `idea.md`，希望在现有视觉巡检能力之上，再做三件事：

1. 建一个粗略的 3D 校园地图，覆盖校园、小区、森林三个场景。
2. 设计决策系统，把监控、巡检机器狗、人工上报统一接入。
3. 形成闭环：发现事件、评估严重性、调度最近设备、回传现场视频、通知安保体系。

现有资产是 `visual_inspection_demo`：四场景 91 项任务的静态展示页、实时推理服务、部分素材。展台时间在下周，约 11 月 9 日那一周。

## 四、关键取舍

### 1. 用密度单点突破，不铺开全部能力

密度的三个优势：对应拥挤、聚集、密度异常三类事件；输出直观，人数与热力图一眼看懂；能独立串起完整处置链，不依赖其他模型。

其他能力放进能力矩阵和路线图，不放进现场必选路径。现场宁可只讲一条完整故事，也不要把九十一项能力都做成半成品。

### 2. 低模 3D，不做写实还原

写实 3D 的成本在建模、贴图、光照和性能，展台只需要空间关系和事件落点。低多边形加纯色块，反而更像指挥系统。

按用户提供的俯视图描轮廓，保留分区边界，不做一比一还原。高度用 0 到 5 的相对等级，不写真实米数。

### 3. 预计算为主，实时为辅

展台最怕模型现场卡顿或误检。三条演示视频提前跑一遍，把每帧结果存成 JSON，播放时叠加。视觉效果与实时推理一致，但稳定。

实时推理只用在两个地方：上传视频环节，以及讲解员主动触发的现场演示。两处都准备预置素材兜底。

### 4. 3D 为主，2.5D 兜底

地图数据与渲染方式解耦。同一份多边形数据，既能给 Three.js 做 3D，也能给 SVG 或 Canvas 做 2.5D。第 3 天设决策门，3D 没到可用状态就切 2.5D，不拖整体。

### 5. 机器狗作为遥控节点，不宣称自主

狗能遥控行走、有摄像头，这已经足够形成“系统指挥设备”的观感。系统发出调度指令，操作员遥控狗前往，屏幕同步显示狗的第一视角。

讲解时说“移动巡检节点”，不说“自主导航”。被问到时回答“当前是遥控节点，自主导航与视觉伺服在下一阶段，调度接口已经预留”。这比含糊其辞更显得成熟。

### 6. 拟真可以，声称已部署不行

展台需要效果，拟真是行业惯例。风险不在模拟，而在话术。

可以夸大的是场景广度、应用愿景、可复制性。不能夸大的是实时性能、自主程度、部署状态、对接状态、准确率数字。

大屏角落放一行“演示原型 · 场景与数据为模拟”。这不影响效果，但能挡掉大部分质疑。

### 7. 一周展台版与三个月项目版分开

展台版目标是把故事讲完整：密度事件、研判、调度、视频确认、处置、闭环。项目版目标是真实接入与多场景复制。

两条路线共用事件 schema 与地图数据，不共用排期。

### 8. 地图按图描，但不加真实布点

用户提供的是校园总平面图，按图描轮廓没有问题。但公开演示不添加真实摄像头位置、盲区、安保点位。这既是安全考虑，也避免把演示变成布防图。

### 9. 事件层是核心资产，地图只是视图

地图好看，但真正可复用的是事件 schema、研判规则、调度逻辑。换一个场景，地图要重画，事件层可以保留。

因此第一周先冻结事件 schema，再做页面。

## 五、方案演化

1. **原始设想**：3D 地图、监控接入、人员监测、调度狗与人、疏散、通知安保、森林消防联动、地铁建模、上传视频闭环。
2. **第一次评估**：方向可行，但不能照字面全做。3D 建模成本高，监控权限没有，模型覆盖不足，闭环只能是演示级。
3. **确定主线**：人员密度是唯一稳定能力，用密度串起完整处置链。其他能力进矩阵与路线图。
4. **确定展台形态**：大屏轮播、笔记本讲解、机器狗道具三层动线。预计算检测为主，实时推理为辅。
5. **确定地图方案**：低模 3D，按俯视图描轮廓，保留分区边界，不做一比一还原。
6. **完成第一版描图**：20 个语义要素，校园外轮廓 60 个点，输出 JSON、预览图与 SVG。
7. **待办**：确认密度模型接口、狗摄像头取流方式、其他模型交付时间，然后搭 3D 骨架。

## 七、风险与边界

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 过度承诺 | 被问“是不是真的”时答不上来 | 边界声明页、问答卡、模拟标注 |
| 3D 延期 | 第 3 天还不可用 | 切 2.5D，数据不变 |
| 模型不稳 | 现场误检或卡顿 | 预计算回放，实时只作补充 |
| 集成失控 | 人多、接口不一致 | 第 1 天冻结 schema、API、地图格式，设总集成人 |
| 狗不听话 | 现场不走或图传断 | 静态道具加预录第一视角 |
| 网络不稳 | 页面加载失败 | 全离线，本地打包 |
| 隐私争议 | 人员监测被质疑 | 不做人脸，只做密度与姿态，边缘模糊 |
| 安全争议 | 公开真实布点 | 地图不标注摄像头与盲区 |

## 八、待确认

1. 密度模型的输入输出形式：视频文件、摄像头序号还是 RTSP；输出人数、检测框还是热力图。
2. 机器狗摄像头的取流方式：RTSP、USB 采集还是手机推流；是否有控制接口。
3. 组内其他模型的交付时间，第 3 天截止后未交付的一律进路线图。
4. 展台讲解人，最好从第一天参与。
5. 地图是否需要真实比例尺；如果需要，请提供图上比例。
6. 真实校园总平面图是否允许公开演示；如果不允许，改用去标识化的示范片区。

## 九、结论

采用“密度驱动的联动处置”作为展台主线，低模 3D 地图作为空间载体，预计算检测保证稳定，机器狗作为遥控移动节点，上传视频作为压轴互动。

一周内交付展台版，三个月内推进项目版。两条路线共用事件 schema 与地图数据。

下一步：确认密度模型与狗摄像头的接口，然后搭 3D 骨架，先用假数据跑通“事件亮起、调度线、状态流转”。
