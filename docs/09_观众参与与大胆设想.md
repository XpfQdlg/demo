# 观众参与与更大胆的设想

版本：2026-11-09
前置文档：`07_移动预警接收页.md`、`08_四大模型场景应用.md`
定位：展台最怕变成「讲解员一直讲、观众站着看」。这一版把四模型应用做成
**观众能亲手触发的一次完整闭环**，并且留了一组更大胆的 v2 想法。

---

## 一、一句话

**扫码 → 拍一张 → 四个模型会诊 → 一键上报指挥中心 → 大屏切到你的场景、
真的把机器狗派出去 → 你的手机收到「观众上报」预警和处置回执。**

观众不只是看客，他的一次上报会真实改变大屏上的 3D 场景和调度流程——
这是展台最容易围人的一段。

---

## 二、观众动线（30 秒）

| 步 | 观众看到 / 操作 | 背后发生什么 |
| --- | --- | --- |
| 1 | 扫大屏二维码，手机打开预警接收页 | 手机连上本机总线，进入实时接收 |
| 2 | 点底部「我要参与 · 上报一次异常」 | 打开参与浮层 |
| 3 | 选场景（校园/小区/地铁/森林）+ 拍一张照片或点「用演示照片」 | 照片只在本机预览，不上传 |
| 4 | 点「让四个模型看一看」 | 照片上出现扫描线与检测框；四个模型逐行点亮：主判模型给识别结果，其余三个模型给交叉复核 |
| 5 | 看结论卡：异常名、置信度、研判理由、处置建议 | 研判文案来自模型的模拟输出（真实模型接入后同名字段覆盖） |
| 6 | 点「一键上报指挥中心」 | 手机 POST `/api/commands`，总线把指令推给大屏 |
| 7 | 抬头看大屏 | 大屏切到上报场景，弹出金色「AUDIENCE · REPORT」会诊面板，四模型结论逐行出现 |
| 8 | 大屏画面自己动了 | 监控层生成一条观众上报异常 → 报警 → 按 A* 派最近的机器狗/人形 → 镜头自动跟随出警设备 12 秒 |
| 9 | 手机弹出「观众上报」预警卡片 | 与普通预警同一套生命周期：发现→派单→到场→处置→完成，卡片挂金色「观众上报」徽标 |
| 10 | 手机收到轻量回执 | 「你的上报：dog-2 已前往（约 28 米）」「已处置完成」 |

如果大屏没开（只开了手机页），总线会自动合成一条完整的兜底生命周期，
手机照样能看闭环——**不会出现「点了没反应」**。

## 三、两种运行模式

| 模式 | 判定 | 行为 |
| --- | --- | --- |
| big-screen | 有页面订阅 `/api/commands/stream` | 指令推给大屏：切场景、3D 真出警、事件推回所有手机 |
| fallback | 没有大屏订阅 | 总线自己合成 alarm→dispatched→arrive→handling→resolved（约 12.5 秒），手机端闭环不受影响 |

手机提交后接口返回 `mode`，页面据此提示「指挥中心正在派单」或照常等待兜底事件。

两种模式交叉时有两道保险：

- 大屏在线但 15 秒内没有响应（切森林/地铁场景较慢、或现场执行体全忙），
  总线兜底补一条生命周期，不让手机卡在「已上报」；
- 兜底已经出警后，大屏迟到的同一条上报不会重复出警：总线按 `command_id`
  匹配，并抑制同场景同类型的迟到重复警报，手机端只出现一张卡。

### 协议

```http
POST /api/commands
Content-Type: application/json

{
  "type": "visitor_report",
  "scene": "campus",          // campus / community / subway / forest
  "kind": "fire",             // fire / crowd / trash
  "confidence": 0.93,
  "name": "明火",              // 场景本地化异常名
  "client_id": "手机本地随机 id",
  "note": "观众手机上报"
}
```

响应：`{ ok, id, mode: "big-screen" | "fallback", listeners }`

- 大屏指挥流：`GET /api/commands/stream`（SSE，`event: command`）
- 状态：`GET /api/commands/health`
- 心跳与断线重连沿用 `EventSource` 自带机制

## 四、大屏与会诊动效的讲解口径

大屏金色面板上四行分别是：

```text
● 校园巡检模型 · 识别到「明火」· 置信度 93%      [主判]
● 小区安防模型 · 复核：周边人员密度正常，无疏散需求 [复核]
● 地铁客运模型 · 复核：客流影响低，无需限流        [复核]
● 森林火险模型 · 复核：烟雾扩散风险可控            [复核]
研判结论：高危 · 校园巡检已下发就近处置指令
```

讲解时可以强调两点：

1. **四个模型是统一接入的**，按场景路由到专属模型主判，其余模型做交叉复核；
2. **从识别到上门是真的**：大屏会用 A* 派最近的执行体，镜头自动跟过去，
   手机同步收到每一步，不是放一段视频。

> 注意：复核台词是展台演示口径，真实系统里是否做跨模型复核需要业务确认；
> 对外讲「演示了多模型协同的设想」，不要讲成已经上线。

## 六、真实 / 模拟边界

| 项 | 现状 |
| --- | --- |
| 拍照与检测框 | 照片只在本机预览，**不上传**；检测框与置信度是模拟展示 |
| 四模型会诊 | 台词为模板生成；真实模型接入后由 `incident.analysis` 覆盖 |
| 手机 → 大屏上报 | 真实可跑：本机总线 POST/SSE；单文件 `file://` 下自动指向本机 5179 |
| 大屏切场景 / 报警 / 派单 / 跟随 | 真实可跑：现有 3D 调度链路 |
| 手机接收处置进度 | 真实可跑：与普通预警同一条 SSE 生命周期 |
| 大屏不开时的兜底 | 总线模拟的生命周期，用于演示不中断 |

## 七、现场运营清单

1. **先开大屏，再让观众扫码**：大屏页面订阅着指挥流，观众上报才会真正切 3D 场景；
   大屏没开会走兜底，手机有闭环但大屏没动静。
2. 手机与大屏电脑连同一 Wi-Fi；二维码取本机第一个非回环 IPv4。
3. 每场演示前 `/api/alerts/reset` 一下（或在页面刷新），清掉上一场的观众上报与事件日志。
4. 多台手机可同时参与；事件会广播给所有手机，别人也能看到「观众上报」徽标。
   目前回执 toast 也会出现在所有手机的 visitor 事件上；如果只想让上报者看到，
   需要总线事件带上 `client_id`（当前协议还没回传，属于下一步）。
5. 照片不上传、不落盘，只在本机做预览；讲解时主动说明，减少隐私顾虑。
6. 大屏边上的观众可以看到会诊面板与自动跟随镜头，讲解员可以顺着说
   「这是他刚刚上报的事件，系统真的把机器狗派出去了」。

## 八、更大胆的设想（v2 路线）

> 2026-11-09 更新：第 1（语音上报）、2（巡检点打卡）、3（值班员角色）、4（战报/排行榜）、
> 5（手机看第一视角）、6（语音指挥大屏）、7（模型盲盒竞猜）已经实现，手机端同时完成
> AEGIS 界面重设计，详见 `10_AEGIS界面重设计.md`。下面保留原始设想，作为后续扩展清单。

按「展台效果 / 投入」排序，前几条都很适合继续加：

1. **语音上报**：手机按住说话「图书馆北侧好像冒烟了」，语音识别（真实
   或模拟）→ 自动填场景与异常 → 上报。比拍照更快，围观的老人小孩也能玩。
2. **AR 巡检点**：展台摆四个二维码/AR 标（校园、小区、地铁、森林），观众扫码
   即「抵达巡检点」，手机摄像头画面叠加检测框，扫完自动生成一次上报。
3. **多人角色扮演**：手机连入时随机/选择身份（安保、消防、巡检），大屏报警
   分发到不同角色手机；手机可以「接单 / 转派 / 到场确认」，大屏显示角色头像
   与响应时间——一下从单人演示变成多人协作。
4. **参与战报与排行榜**：大屏角落显示今日参与人数、上报次数、四模型识别
   分布、最快处置记录；散场时投一张「本场 AI 安保战报」。
5. **手机看机器狗第一视角**：机器狗到场后，手机详情里出现「现场回传」窗口
   （可先用大屏小窗的渲染画面做模拟，真实时可接狗的摄像头）。
6. **语音指挥大屏**：「去操场看看」「把 3 号狗叫回来」，大屏语音回复并执行，
   配合展台讲解非常出效果。
7. **模型盲盒 / 人机竞猜**：同一张图先让观众猜异常类型，再揭晓模型判断与
   置信度；猜中送小礼品，模型讲错时反而更能引出「模型边界」的讨论。
8. **真实模型接入**：上传一段视频或 RTSP 抽帧，走真实 YOLO/密度模型，
   把检测框和置信度如实展示；这是从「演示」走向「可信」的关键一步。
9. **实物联动**：展台放一台遥控机器狗，观众上报后由讲解员/脚本驱动实物狗
   走到观众面前，手机和大屏同步显示「实物已出动」。
10. **沉浸式剧情**：把四个场景包装成「某校园安全演练日」，观众扫码成为
    「值班员」，处理完 3 个事件后升级，大屏给表彰动画——让排队的人愿意等。

> 其中 1、2、4 可以在现有总线上直接加页面/端点，不需要改 3D；
> 3、5、9 需要动大屏状态机与设备，属于下一阶段。

## 九、边界提醒

- 展台演示可以大胆，但对外表述要区分「演示设想」与「已部署能力」；
  真实模型未接入、照片检测为模拟，这两句不要省。
- 观众上报不写入任何真实系统，只作用于本机总线与展台 3D 场景。
- 大屏开着时上报才会切场景出警；讲解员离场前确认手机页与大屏页都正常。
