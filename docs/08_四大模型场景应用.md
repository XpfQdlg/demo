# 四大模型 · 场景应用（展台讲解口径）

版本：2026-11-09
前置文档：`02_技术方案.md`、`03_联动指挥方案.md`、`07_移动预警接收页.md`
用途：对外讲解「四个场景各一个模型，怎么应用到巡检里」，以及明确哪些是真的、哪些是演示模拟。

---

## 一、一句话定位

**四个场景各配一个专属模型，统一接入指挥中枢：模型识别 → 风险研判 → 就近调度 → 手机触达。**
3D 场景只是给观众一个空间参照，不追求精细建模；这一版把重点放在
「模型怎么被用起来」和「预警怎么到达人」上。

四个模型都没有在展台现场跑真实推理，模型输出是规则 + 模板的模拟数据；
但事件契约、调度、状态机、手机推送都是真的，接真实模型时只换数据来源，不改链路。

## 三、应用链路

```text
① 模型识别          ② 风险研判            ③ 就近调度             ④ 移动触达
按场景路由到        等级 / 置信度 /         A* 选最近的空闲设备     预警与处置进度
专属模型，识别异常   研判理由 / 处置建议     （狗 / 人形）           实时推到手机
```

| 环节 | 当前实现 | 接真实系统时 |
| --- | --- | --- |
| ① 模型识别 | 3D 监控层按场景产生模拟报警 | 换成真实模型服务回调；事件字段不变 |
| ② 风险研判 | 规则 + 模板文案，按异常类型给等级、置信度、理由与建议 | 换真实研判模型/LLM，覆盖 `incident.analysis` 即可 |
| ③ 就近调度 | **真实可跑**：A* 折线长度选最近空闲执行体，到场/扫描/处置/复位全链路 | 换成真实机器人任务接口 |
| ④ 移动触达 | **真实可跑**：本机总线 SSE，手机与电脑同局域网实时接收 | 换成服务端 WebSocket / 推送，接口形状不变 |

> 展台讲解时建议把③④两句说得实一点：调度和推送是本项目真的做出来的；
> ①②两步现阶段是演示模拟，不要说成已在真实场地跑通。

## 四、演示动线

### 大屏（3D 页面）

1. 顶部模型条：切「校园 / 小区 / 森林 / 地铁」页签，模型条同步变为
   「校园巡检模型 / 小区安防模型 / 森林火险模型 / 地铁客运模型」，
   并显示该模型的覆盖范围。
2. 每个场景三个摄像头自动循环报警：
   - 右侧事件流的报警行带方括号简称：`【校园巡检】教学区 12东侧发现明火`；
   - 底部消息条是完整一句话：`校园巡检发现…，已呼叫最近的 dog-3 前往…`；
   点地面可手动派单。
3. 右上角「手机」弹出二维码，请观众用手机扫码。

### 手机（预警接收页）

1. 场景条显示当前模型；卡片上标注「● 校园巡检模型 · 置信度 93%」。
2. 点开预警详情：
   - **四模型接入**：四个模型 chip 全部列出，本起由哪个模型主判高亮；
   - **应用链路**：模型识别 → 风险研判 → 就近调度 → 移动触达，按当前状态点亮；
   - **模型研判**：置信度、识别来源、研判理由、处置建议。
3. 右上也点「模型」按钮，打开四模型应用总览：4 张模型卡 + 应用链路 + 今日预警数，
   适合讲解时停在概览上回答「你们有几个模型、分别看什么」。
4. 如果没连大屏（演示模式），手机会按 校园 → 小区 → 地铁 → 森林 自动轮换，
   每个场景报两起，四个模型各演一遍。
5. 观众参与：手机底部「我要参与」→ 拍照 → 四模型会诊 → 一键上报 →
   大屏切到对应场景，金色「观众上报」会诊面板逐行亮起，机器狗真实出动并自动跟随。
   详见 `09_观众参与与大胆设想.md`。

### 两分钟讲解话术（可直接背）

> 我们覆盖四个场景，每个场景配一个专属模型：校园巡检模型负责消防、实验室和道路设施；
> 小区安防模型看出入口、楼栋和消防通道；地铁客运模型管通道占用、遗留物和客流安全；
> 森林火险模型看火险、病虫害和林道。四个模型统一接入指挥中枢，大屏切到哪个场景，
> 就路由到哪个模型。模型发现异常后先给出等级、置信度和处置建议，系统再按路径长度
> 派最近的机器狗或人形机器人到场；从发现、派单、到场到处置完成，每一步都实时推到手机。
> 手机上不只是一条报警，还能看到这次是哪个模型识别的、置信度多少、研判理由是什么。
> 目前 3D 场景和模型输出是演示级的，调度和移动推送是真实可跑的；把真实模型接进来，
> 只需要替换分析结果这一层，链路不用动。

## 五、边界（对外讲清楚，避免夸大）

| 项 | 现状 |
| --- | --- |
| 3D 场景 | 低模示意，按总平面图描轮廓；不追求写实，短期也不会做更精细 |
| 模型识别 | 演示模拟：按场景产生固定类型的报警，不是现场真实推理 |
| 模型研判 | 规则 + 模板文案；置信度是稳定的模拟值，不是真实模型输出 |
| 调度与状态机 | 真实可跑：A* 就近派单、到场、扫描、处置、复位、循环 |
| 手机接收 | 真实可跑：本机总线 + SSE，多台手机可同时看，断线自动重连 |
| 真实设备 | 未接入真实监控与真实机器狗遥控；机器狗是程序化模型 |
| 视频回传 | 素材目录为空，接口与降级路径就绪，未接真实视频 |

## 六、接真实模型要改哪里

1. **分析结果**：在事件 `incident.analysis` 里写
   `{ confidence, detect, rationale, suggestion }`；手机端会自动优先用它，
   缺失时回退到 `default_analysis()`。相关代码：`src/mobile/contract.js`。
2. **识别来源**：大屏侧 `src/core/alert_publish.js` 组装事件，把真实模型名、
   检测框、置信度带进来即可；也可以把 `alert_bus.mjs` 换成服务端接口。
3. **模型清单文案**：`SCENE_MODELS` 里每个模型的能力项、覆盖范围都是展示文案，
   换口径只改这一处，大屏与手机同步生效。
4. **模型数不是固定的**：如果以后不是「一场景一模型」，把 `SCENE_MODELS` 结构与
   手机详情里的四模型 chips 改成按事件里的 `model_id` 匹配即可。

## 七、四模型能力清单（摘要）

> 完整清单见 `source/各组人员任务表.md`，这里是讲解时够用的摘要。

**校园巡检模型**：消防设施（灭火器/消防栓/防火门/安全出口/消防通道）、烟雾火焰、
教学楼巡检（积水/门窗/照明/垃圾）、校园道路（积水/障碍/井盖/非机动车）、
宿舍公共区（漏水/电动车入楼/楼道堆物）、实验室安全（机械开关/液体泄漏/仪表读数/指示灯）、
设备设施（围栏/电梯外观/路灯）、人员聚集。

**小区安防模型**：出入口拥挤、人员异常聚集、电动车违规停放与入楼、烟雾火灾、
防火门状态、井盖与道路障碍、路面破损、地面积水、垃圾满溢、楼道堆物、
围栏破损、地下车库灯具故障、消防栓与灭火器识别。

**地铁客运模型**：妨碍通行物品、遗留物品、人员密度、跌倒与异常行为、
地面积水/湿滑、仪表读数、指示灯与开关状态、消防器材、垃圾桶满溢、
公共设施破损、液体泄漏、管路锈蚀、防火门/疏散标识、售票机与台阶门体状态。

**森林火险模型**：明火/烟雾/微烟雾、树干虫害与病害、树叶虫斑病斑、
吸烟行为、倒木与断枝、林间道路障碍、消防器材、林区垃圾。

## 八、可以继续做的

- 上传视频触发模型：讲解员现场上传一段视频，走一遍真实推理→研判→推送，
  展台互动性最强，也是 `idea.md` 里最早提的想法。
- 模型切换演示：手动指定「用哪个模型看哪个场景」，对比四个模型的关注点差异。
- 真实模型接入：按 §6 替换分析层，手机端与总线不用改。
