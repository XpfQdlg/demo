# 大会展台手册（现场用）

一句话：**一块大屏讲四个模型，两块小屏让人参与。**

大屏是「AEGIS 城市风险中枢」：夜里发光的数字孪生沙盘 + 左侧四模型值守栏 + 右侧事件流 +
底部四段链路。讲解员用平板点一下情景，观众用手机拍一张照片，都会走同一条链路：

```text
现场发现异常 → 四个模型会诊（主判 + 三个复核）→ 切到对应场景
            → 就近调度最近的机器狗 / 人形 → 到场处置 → 手机收到回执
```

---

## 一、三块屏

| 屏 | 地址 | 谁用 | 作用 |
| --- | --- | --- | --- |
| 大屏 | `http://<局域网IP>:5179/cinematic.html` | 展台主屏 | 四模型值守、演练/平板会诊全屏、观众回执右下角、3D 出警 |
| 平板 | `http://<局域网IP>:5179/tablet` | 讲解员 | 12 个情景按钮，点一下就触发大屏整屏会诊 |
| 手机 | `http://<局域网IP>:5179/phone` | 观众 | 拍照后自动分析上报、右下角回执 |

三块屏必须连**同一个 Wi-Fi / 同一个网段**。大屏左下角的二维码会自动指向本机 WLAN 地址。

---

## 二、开机清单

1. 电脑连展台 Wi-Fi，记下 IPv4（`ipconfig`，看「WLAN」那一行）。
2. 起服务：

   ```bash
   cd command_demo
   npm install        # 第一次
   npm run dev
   ```

3. 大屏浏览器打开 `http://localhost:5179/`（会自动跳到观感版），按 `F11` 全屏。
4. 平板浏览器打开 `http://<局域网IP>:5179/tablet`，加书签、锁横屏、调高亮度。
5. 自己手机扫一次大屏左下角二维码，确认能打开 `/phone`，再退出。
6. 大屏右上角「在线终端」出现数字，说明手机已连上总线。

> 没有网络也能讲：双击 `command_demo/观感版演示.html` 可离线跑完整 3D 与四模型 HUD。
> 但手机上报与平板控制需要 dev server，离线包不含总线。

## 三、大屏自己会做什么

无人操作时，大屏按下面的节奏自己演，讲解员随时接管：

| 时间 | 行为 |
| --- | --- |
| 0–9 秒 | 场景加载，镜头缓慢横移（约 0.006 rad/s），留出安顿时间 |
| 9 秒后 | 现场第一起自然报警（之后每 17 秒左右一起），事件流开始滚动 |
| 45 秒后 | 每 26 秒无操作，自动切下一个场景，切场时有黑底「场景链路」幕 |
| 约 80 秒后 | 每 80 秒左右、且 45 秒无人操作时，自动走一次「四模型会诊 → 出警」演练 |
| 有人操作 | 自动切场暂停 26 秒；自动演练需要安静 45 秒才恢复 |

自动演练的标题会写「自动演练 · 现场发现「X」」，事件流写「【自动演练】」，
不计入「观众参与」人数。观众真实上报会计入。

### 现场节奏建议

- **开场 30 秒**：停在校园页，让镜头自己走。说「这是四个模型共同值守的一座城」。
- **第 1 分钟**：平板点「校园 · 明火」。看全屏会诊四张卡依次亮，结论条写「已派 dog-3 前往」。
- **第 2 分钟**：切森林，指出火点与烟柱；再切地铁，指出站厅与遗留物识别。四个场景各 15 秒。
- **第 3 分钟**：请领导/观众扫码，拍一张，等进度条走完自动上报。大屏右下角弹回执、切场景，
  并真的把设备派过去，手机随后收到「已上报」。这是全场唯一「观众改变大屏」的瞬间，留足时间。

## 四、讲解词（可直接念）

> 「我们把四个垂直场景的模型接进了同一个指挥中枢：
> 校园巡检、小区安防、地铁客运、森林火险。
> 左边这四张卡就是四个模型，各自有识别任务数和今日预警。
>
> 一旦有异常，不是只报一个警：四个模型会同时看一眼——
> 主判模型给结论和置信度，另外三个模型做独立复核，确认不是误报。
> 然后中枢就近调度，把最近的机器狗派到现场，全程不用人点。
>
> 您也可以参与：扫这个码，拍一张您看到的现场，四个模型会当场会诊，
> 结果直接送到这块大屏上。」

边界口径：**识别与研判是模拟输出，调度与消息推送是真实跑的**；不要说「已在某地部署」。

## 五、观众/领导参与的两种方式

### 1. 手机扫码（观众）

- 大屏左下角二维码 → `/phone`
- 首页黑色卡片「拍一张现场照片，让四个模型一起看」→ 上报页
- 选场景 → 拍照（或「用演示照片」）→ 进度条自动分析并上报，画面回到预警列表
- 大屏：右下角回执（不进全屏）→ 切场景 → 派单；手机：右下角「已上报，指挥中心会收到」
- 观众不需要点「确认上报」，拍完等两秒即可

### 2. 平板点选（讲解员 / 领导）

- 四张模型卡 × 三个情景（高危 / 中危 / 低危）
- 点一下 = 发一条 `visitor_report`，与大屏收到手机上报完全同一条链路
- 适合领导上台时「您点一个」——不用扫码，零等待

## 六、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 二维码扫开「无法访问」 | 二维码用了 Hyper-V / 虚拟网卡地址 | 已过滤虚拟网卡；仍不对就在地址后加 `?bus=http://<WLAN IP>:5179` |
| 平板显示「大屏未连接」 | 大屏没开，或不在同一网段 | 先开大屏；确认两台设备 IP 前三段一致 |
| 大屏只有黑底和窗光 | 显卡弱 / 集显 | 地址后加 `&q=low`；或在右上角切低画质 |
| 画面卡顿 | 4K 屏 + 高画质 | 用 `q=medium`，窗口 1600×900 |
| 手机收不到预警 | 手机页面停在后台 | 重新打开 `/phone`，顶栏出现「实时接收」 |
| 自动演练太频繁 | 现场一直没人操作 | 讲解员随手点一下平板/拖动画面，自动演练会安静 45 秒 |
| 想立刻演一遍 | 等 80 秒太久 | 大屏控制台执行 `__drill()` |

## 八、已知取舍

- 建筑是低模体块 + 亮窗，不做真实建模；夜间灯光与窗光是主要观感来源。
- 地铁站厅的曝光单独压了一档，否则浅色混凝土会过曝。
- 森林的火点是示意的固定点位，不随调度变化。
- 大屏底部链路条只反映最近一条事件；连续快速上报时会跳步。
