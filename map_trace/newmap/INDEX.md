# 新地图处理 · 代码索引

把用户标注的新地图与原图建筑合成 3D 场景数据包，供 `../../command_demo` 使用。

---

## 一、两张图的关系

| 图 | 文件 | 尺寸 | 提供什么 |
| --- | --- | --- | --- |
| 新图 | `../../source/maps/campus_zoning_outline_1079x1554.jpg` | 1079 × 1554 | 区域轮廓（学校、森林、小区、地铁站）、道路线 |
| 原图 | `../../source/maps/campus_overview_960x1218.png` | 960 × 1218 | 20 栋建筑的轮廓与高度档 |

两张图**不是严格的几何复制**：用边缘配准（ECC）算出的相关系数只有 0.10，
按周长做弧长对应拟合的残差达 340 像素。所以不能直接当作同一张图的缩放。

但**校园包围盒**对应得很好：宽高比 0.7776 对 0.7747，按包围盒做相似变换后，
人才公寓正好落在新图的品红框内，教学楼、图书馆、田径场也都落在道路围合的地块里。
因此用包围盒变换迁移建筑是可靠的。

## 三、文件清单

| 路径 | 作用 |
| --- | --- |
| `extract_zones.py` | 按色相提取五个区域轮廓，输出 `map_zones.json` 与核对图 |
| `build_roads.py` | **把黄线重建为道路几何体**、按道路裁边建筑、算行道树点位 |
| `build_map_package.py` | 迁移建筑坐标、生成行走掩膜与地面贴图，打包成 `map_package.json` |
| `map_zones.json` | 五个区域的多边形（像素坐标） |
| `map_roads.json` | 道路路面 / 白色边线多边形、行道树与灌木点位 |
| `buildings_clipped.json` | 按道路裁边后的建筑（可能一栋变多块） |
| `map_package.json` | **最终数据包**：区域、建筑、道路、行道树、行走掩膜、比例尺 |
| `ground.png` | 地面贴图，只有校园铺装与绿地森林，**不画道路**（道路是几何体） |
| `roads_check.png` | 道路核对图：黑路面 + 白边线 + 绿树点 + 灰建筑 |
| `walk_mask.png` | 行走掩膜预览，白色为可通行 |
| `zones_labeled.png` | 区域编号核对图 |
| `buildings_overlay.png` | 建筑迁移到新图后的核对图 |
| `align_campus_bbox.png` | 新旧图按校园包围盒叠加的核对图 |

## 四、运行顺序

```bash
# 1. 区域轮廓
python extract_zones.py

# 2. 道路重建 + 建筑裁边 + 行道树（依赖上一步的 map_zones.json 与旧 map_package.json）
python build_roads.py

# 3. 数据包（含建筑迁移、裁边覆盖、掩膜、地面贴图）
python build_map_package.py

# 4. 拷进前端
cp map_package.json ground.png ../../command_demo/src/map/data/
```

**顺序不能颠倒**：`build_roads.py` 读的是上一版 `map_package.json` 里的建筑，
`build_map_package.py` 再读 `buildings_clipped.json` 覆盖它。
换地图时先删旧的 `buildings_clipped.json` 再从第一步跑。

## 五、关键参数

- 比例尺：**1 像素 = 0.5 米**，校园约 454 × 586 米。这是估算值，拿到实测尺寸后改 `build_map_package.py` 里的 `METERS_PER_PX`。
- 高度档：0 到 5 档分别对应 0 / 4 / 8 / 14 / 20 / 26 米，定义在 `HEIGHT_M`。
- 道路：黄线是**中心线**，膨胀到 **8 米**总宽；白色边线从外沿向内 **0.3 米**。
- 建筑退让：建筑压到「路沿 + 0.6 米」范围内的部分被裁掉，20 栋 → 52 块；裁完小于 **45 平方米** 的碎块丢弃。
- 行道树：离路沿 **2.2 ~ 4.2 米**，间距 **15 米**，按 1.8 米树冠与建筑保持距离。
- 行走掩膜：1/4 分辨率（269 × 388），建筑外扩 2 米后挖空，再并上路面；可行走面积 19.5%。

## 六、道路为什么要做成几何体

旧做法把黄线稍微膨胀后直接画进 `ground.png`。两个问题：

1. **分辨率不够**。底图 1 像素 = 0.5 米，0.3 米的白色边线只有 0.6 像素。
   第一人称贴地平视时路面就是一片糊掉的深灰，看不出是路。
2. **和建筑打架**。建筑轮廓从旧图迁移、道路从新图标注，两者几何不严格一致。
   旧做法下道路有 40.4% 的面积落在建筑轮廓内部，俯视能直接看到
   路冲进教学楼然后消失，这就是穿模。

现在道路是独立网格（`ShapeGeometry` + 内洞），黑色沥青面压在白色边线上方 8 厘米，
边线只露出外沿一圈。建筑轮廓同时按路面裁边，路面连续、建筑局部收边。

那 8 厘米层间距是必要的：只差一两厘米时，两百米外的俯视会因深度精度不足
出现黑白相间的条纹（z-fighting）。

## 七、已知问题

1. 建筑位置按包围盒变换迁移，是近似对齐，不是精确配准。单栋建筑可能有几米到十几米的偏移。
2. 原图 `out/map_features.json` 里的 `campus_boundary` 存的是半分辨率坐标，与 `features` 的全分辨率坐标不一致，用之前要乘 2。
3. 新图只有道路和边界，没有建筑；原图有。两者的几何并不严格一致，见第一节。
4. 裁边损失最大的是 `lab_center`（7 块，56%）与 `talent_apartment`（6 块，55%），
   道路恰好从建筑中间穿过。接受不了的话需要回标注图调整黄线走向，不要改代码。
