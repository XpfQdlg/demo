## 一、为什么只取骨架，不逐点描图

两张图都不是可直接矢量的素材：

- 总平面图是 2018 年扫描件，山体是等高线 + 植被纹理，自动分割会发毛。
- 卫星图整体偏暗（均值 121/255），暗色屋顶连成一片，楼栋轮廓提不干净。

因此方案是：**从图上取走向与排布关系，细节用参数化几何补**。
山体高度场由 `terrain.js` 的钟形函数生成，小区楼栋按内接矩形排布。
这样换图只改轮廓点，不用重新描所有的细节。

## 三、运行

```bash
python build_scene_extra.py        # 首次生成，或两山 / 地铁参数有改动时
python expand_community.py         # 改小区范围
python enrich_community.py         # 改小区内部排布（需要在 expand 之后跑）
python split_long_buildings.py     # 改楼体切分规则
python fix_road_conflict.py        # 改完楼体后必须再跑一次，把路面从楼底下挖掉
```

依赖 numpy、opencv-python。不需要其他前置数据，读的是已在用的 `map_package.json`。

## 四、关键口径

**坐标**：一律像素坐标，1 像素 = 0.5 米，与 `map_package.json` 一致。

**西山轮廓**：东边界收到 x ≈ 205，与校园（西边界 x ≈ 318）之间留出 40 米带子，
巡检空地（x 212..300、y 892..1012）整块落在这条带子里，不与山体重叠。
必须这样布置：空地若压在山体内，压平后山脚会在场地边缘陡然立起，第一人称看过去是一堵绿墙。

**东山轮廓**：从图幅东北角铺到东侧，主要用作校园远景。

**小区**：现在是校园东侧一条 177 × 155 米的楔形地块，19707 平方米。
楼栋与环路一律用**栅格腐蚀**求内缩轮廓，不用几何内缩——轮廓有凹口和斜边，
内缩会在凹角甩出尖刺或自交，实测过两次都失败了。
环路按边界内缩 9 米（宽 6.5 米），可建区按 20 米；楼栋从大到小贪心摆，
每步检查四角与四边中点都在可建区内，楔形区域也能填满。

**地铁**：站台 12 米宽、0.9 米高，两端 6 米处设停止线；列车 4 节编组、20 米一节，
周期 30 秒、停站 8 秒、单侧进站距离 260 米。
进站距离不能太大：超出站厅长度太多时，车长时间停在画面外，看起来像没有车。

## 五、路面与楼体的冲突

建筑从旧图迁移，道路从新图标注，两套几何对不齐。实测 **38 栋楼里有 28 栋压在路面上**，
最大的 `teaching_1` 重叠 3105 平方米。

3D 里路面是贴地几何、楼体从地面拔起，路面会从楼脚处钻进楼里再露出来，
白边线沿着墙根横穿，看起来就是楼和路互相穿模。

处理原则是**楼体为主，路面让位**：`fix_road_conflict.py` 把楼体下方的路面挖掉，
楼体外扩 1 米给路沿留余量。处理时有两个坑：

1. 必须用 `RETR_CCOMP` 而不是 `RETR_EXTERNAL`。整栋楼落在路面内部时，挖掉后形成的是「洞」，
   `RETR_EXTERNAL` 只取外轮廓，洞被丢掉，等于没裁。
2. 边线层是同一批多边形向外扩 0.45 米，要用同一张楼体掩膜一起裁，否则白线还会从楼里穿出来。

裁完从 28 栋降到 1 栋（27 平方米，在 1 米余量以内）。

## 六、已知问题

1. 两山轮廓是手工描的粗多边形（西山 13 点、东山 21 点），走向对，细节不精确。
   要更准需要更高分辨率的图，或用等高线数据（DEM）。
2. 山体高度是参数化的，不是实测高程。峰值按图面估算：西山 46 米、东山 58 米。
3. 小区楼栋按卫星图看到的行列排布重建，不是逐栋描图。扩大后的 7 栋是程序生成的近似布局，
   不是实测。
4. 比例尺 1 像素 = 0.5 米仍是估算值，整条链路都依赖它，拿到实测尺寸后要一起改。
