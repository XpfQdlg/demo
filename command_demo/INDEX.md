## 三、运行

```bash
# 开发预览
npm install
npm run dev          # http://localhost:5179

# 截图验收
node tools/checks/shot.mjs --out=shots/a.png --wait=3000

# 单文件打包（最终交付物）
npm run bundle        # 等价于 node tools/bundle.mjs --clean

# 单文件离线验收：四场景截图 + 贴图解码检查
node tools/checks/file_check.mjs

# 用构建产物演示（同样监听 0.0.0.0:5179，手机预警页与总线都可用）
npm run build
npm run preview

# 手机预警页验收（先起 dev server 或 preview）
node tools/checks/_alert_bus_probe.mjs
node tools/checks/_mobile_probe.mjs
```

手机预警页：dev server 起来后，手机与电脑连同一 Wi-Fi，扫码或直接打开
`http://<电脑局域网IP>:5179/phone`。详细链路见 `../docs/07_移动预警接收页.md`。

最终产物是观感版 `cinematic.html`，交付形态是 `观感版演示.html`。展台直接双击该文件，不需要 Node 与网络。

## 四、操作

| 按键 | 作用 |
| --- | --- |
| `1`–`9` | 切换当前场景内的执行体 |
| `V` | 第一人称 / 俯瞰切换 |

顶栏右侧三个按钮：剧本一至三、轮播、俯瞰。指挥图右上两个小按钮分别是全局切换与放大。

## 五、关键约定

**坐标**：数据层与接口层一律像素坐标，只在 `map/coords.js` 转世界坐标。比例尺取自 `map_package.json`（当前 `meters_per_px` 为 1.0；旧文档与 note 字段写 0.5，口径待实测校正），地图换版只换数据包。

**寻路**：所有场景统一走 A*，网格来自 `nav_grid.js`，每个场景有两套：
`all`（机器狗，建筑与轨道之外都行）与 `road`（人形机器人，只走道路 / 站台面）。
网格按多边形栅格化现场生成，扫描线填充，2 米一格；改数据包即刻生效，不用重跑 Python。
拿不到路径时返回 `null`，不退回直线；调度与手动导航只提示、不移动（见下方「没有路径就不动」）。

**站位**：用最远点采样（`spread_spots`）而不是「按开阔度排序再卡最小间距」。
后者会把设备全挤在同一片空地上，四台机器看起来挤成一堆。

**自动巡检**：`patrol.js`。空闲设备从场景的 `patrol_points` 里挑一个较远的点走过去，
到点停 2~5 秒再挑下一个；事件调度或手动导航时立刻让位。巡检期间 status 仍是 `idle`，
所以随时可被调度。

**到点判定**：`advance_along_route` 对终点用 1.2 米容差、中间航点用 0.5 米。
早先终点也按 0.4 米算，可实体自己的到达阈值是 0.28 米，两者不一致会让设备在
「我认为到了」和「这里认为没到」之间来回切，表现是到点后原地打转。
另有 3 秒卡住兜底，磨不过去就判到达。

**没有路径就不动**：`route()` 拿不到 A* 路径时返回 `null`，绝不退回直线。
直线会穿楼、穿轨道、翻山，正是「机器从楼里穿过去」的来源。
调度与手动导航拿到 `null` 都只提示、不移动。

**切分段的收缩**：`map_package.json` 里 id 形如 `xxx_sN` 的段来自同一栋长楼，
数据上相邻共边（间距 0 米）。渲染时按质心缩 2.6 米，独立楼不缩。
不缩的话西北方向会连成两三百米的一堵墙。

**屋顶设备**：`add_roof_clutter` 现在接受 `outline`，逐件判定是否落在屋面内。
异形楼（L 形、切过的段）按包围盒撒机组会把设备撒到屋面外，远看是一排悬空细条。

**小区页签的楼**：`scene_community.js` 的 `package_buildings_in_zone()` 直接画数据包里的
真实楼（人才公寓 p2~p6）。校园场景传 `packageBuildings: false`，因为它已经把
`PACKAGE.buildings` 全部画过一遍，否则同一栋楼叠两层。

**数据是可生成物**：`map_package.json`、`ground.png`、`scene_extra.json` 都有对应脚本，
改动要走 `map_trace/newmap2/` 下的脚本，不手改。跑的顺序见
`docs/04_观感版整改方案.md` 第 9.4 节。

**行人**：`crowd.js`。每个场景十几个人，只在可行走网格上活动，
人形走 `road` 网格，不会进楼、不会下轨道；目标点选 40 米内且沿途直线可达的位置。
密度告警点位另有 `crowd_cluster` 摆一圈静止的人，否则画面空无一人却说检测到拥挤，讲解说不通。

**动作频率**：步频与转身速度按真人调过。机器狗 `stride = 1.8 + speed × 1.6`、
转身 1.8 rad/s；人形 `stride = 1.9 + speed × 2.4`、转身 1.6 rad/s。
早先偏快，看起来像快进。

**2D 指挥图点击导航**：单场景态点底图任意位置，`minimap.unproject` 反算像素坐标后
派最近的空闲设备；点设备标记仍是切换视角。与 3D 画面点击共用 `app.navigate_to_px`。

## 六、观感版口径

**素材**：AmbientCG（CC0）12 套 PBR 材质，每套 Color / Normal / Roughness / AO 四通道，
1024 压到 512 转 WebP；Poly Haven（CC0）全景天空压到 2048。合计 5.4 MB。

**预载顺序**：`preload()` 必须在建场景之前 await。材质在创建时就去缓存里取贴图，
取不到会退化成纯色，之后再补也来不及——着色器已经编译过了。

**并发限制**：预载内部按 8 个一组限流。四百多张同时发会把浏览器连接池打满，
`TextureLoader` 的 onError 会全部触发（实测 442/442 失败），单张加载却是成功的。

**背景不用全景照片**：实拍全景自带另一套建筑与地平线，与近处 3D 尺度对不上，
远看就像两张图拼接。改成 `set_sky()` 的程序化渐变天空，配合同色雾，
地面一路淡出到天空，没有接缝。全景图只用于环境照明与反射。

**远景**：`add_distant_town()` 在 200~360 米外摆几组无细节体量。
必须**成组**摆，不能随机撒点：随机撒出来是一地零散木箱，成组才有街区的朝向与间距，
雾一糊就读成城郊。组内楼栋沿同一朝向排，组间留空。

**UV 尺度（踩过坑）**：three 里不同几何体的 UV 单位不一样，混用就会把材质铺成噪点或一整块。
- `ShapeGeometry` / `ExtrudeGeometry`：UV **单位是米** → `repeat = 1 / 贴图米数`
- `BoxGeometry` / `PlaneGeometry`：UV 是 0~1 → `repeat = 面尺寸 / 贴图米数`

`pbr()` 的 `repeat` 可以传数字或 `[u, v]`。长宽差别大的盒子（185 × 47 的站厅地面）
必须分开给，否则贴图会被拉成横条。

**repeat 不进缓存**：贴图缓存按 `slug/channel` 建，`repeat` 在材质创建时克隆一份贴图再设。
早先按 `slug/channel/repeat` 缓存，结果是「改了一个 repeat 值就取不到纹理」，
整个场景退化成纯色白模——校园场景上真实发生过一次。克隆共享 `texture.source`，
three 的 WebGLTexture 按 source 缓存，不额外占显存。

**设备复用**：观感版场景里的机器狗与人形机器人不另写一套，直接复用联动演示的零件——
`entities/dog.js`、`entities/humanoid.js`，寻路走 `routes.js` 的 `route()`（狗 all 网格、人形 road 网格），
航点用 `pathfind.js` 的 `spread_spots()`，折线推进用 `dispatch.js` 的 `advance_along_route()`。
行为与 `patrol.js` 一致：挑一个较远的航点到点后歇 2~5 秒。实体子树标了 `userData.no_merge`，
`merge_static` 会向上检查祖先，整棵子树跳过——否则腿会被烘成静止几何，走起来只剩整体平移。
两台设备的出生点要互相避让，否则航点表小的时候（地铁站台只有一条矩形）会生在同一个点上互相穿模。

**合并必须跳过 InstancedMesh**：它的顶点只有一份，位置全在 `instanceMatrix` 里，
合进来会丢掉每个实例的位置——东北山上三百棵树会塌成原点的一棵。

**监控与调度口径**（`src/cine/monitor.js`）：

- 观感版没有 `World`，主演示的 `core/events.js` 用不上，这里只做最小一层：
  摄像头 → 报警 → 派最近的空闲设备 → 到场扫描 → 处置 → 关闭。
- 与 `robots.js` 的接口只有两个字段：`status`（idle / moving / on_site / busy）与
  `task`。有 `task` 时 `robots.step()` 不自己挑航点，走完折线回调 `task.on_arrive()`。
- **距离按折线算，不按直线**。直线近但中间隔着楼，机器走不过去；
  求不出路径的候选直接跳过。`find_path_on` 会把起点吸附到最近的可走格心，
  这段吸附距离要补回总长，否则人形站在草地上会被报成「约 5 米」，其实人还在二十米外。
- **摄像头与巡检航点会同源**：两边都用「开阔且分散」的取点规则，点位撞在一起时
  报警会变成「已呼叫 4 米外的机器前往」。选点位要同时避开设备当前位置与巡检航点。
- **道具不能每轮重建**。`kit.fireFlame` / `smokePlume` 把闭包塞进 `addTick`，
  删掉网格也不会注销 ticker，循环报警每轮重建会越攒越多。道具建一次，处置完隐藏，下一轮显示。
- 小区页签复用校园场景，但 `spread_spots` 是全场撒点、筛进小区只剩一两个，
  所以限定范围的页签要自己在范围内扫格子取候选点。
- 区域名：校园与小区按「离楼脚 15 米内的最近一栋楼 + 方位」取名；
  森林与地铁是独立场景，不套校园楼名，退回「西山林区东侧」「地铁站厅」这种场内方位。

**居民楼方正化口径**（`src/cine/rectify.js`）：

- 先在楼体主朝向上求最小面积包围矩形，再沿短边切 13 米一条，每条取「确实落在原轮廓内」
  的连续区段成一个矩形。板楼至少 7 米长，切出来的总量不到原轮廓一半就整体放弃、退回原形。
- **矩形只能往里收，不能往外扩**。外扩会盖住可行走区，机器人和行人就会从楼角里穿过去，
  而这个网格是按原轮廓挖的，不会跟着变。所以采样时要求每个位置五分之四以上落在轮廓内。
- 拆成板楼后女儿墙可以打开：轮廓是独立矩形，没有相邻块压顶外溢的问题。

**活动范围与地面高度**：

- `add_robots` 的活动范围有三种口径，可叠加：`center_px` + `radius_px` 圆形（小区）、
  `area_px` 多边形（校园按校界）、`exclude_px` 多边形（校园里挖掉小区）。
  只滤航点，不滤路径——两端都在范围内，A* 的最短路一般不会绕出去。
- 地铁站台比地坪高 0.9 米。设备、行人、摄像头、光圈全部要按 `floor_y` 抬起来，
  **少抬一处就会露馅**：行人腿埋在台面里，看着像只有上半身。

**地面光圈**：头顶牌子是屏幕空间、固定约九十像素宽；地面圈是世界尺寸的。
远景时 8 米的圈只有二十几像素，整个被牌子压住，等于没画。
所以按 `cine.distance / 90` 放大，上限 6 倍，始终比牌子大一圈。
圈用「淡面 + 亮边」两层，不用贴图（贴图版在这个场景里没渲染出来，排错花了不少时间）。

**光照跟随场景**：`focus_sun(center, radius, azimuth)`。
平行光方向处处一致，但阴影相机有范围限制，场景不在原点时会整个丢阴影；
方位角按相机方位 +1.15 弧度取，保证朝向镜头的墙面受光。

**性能**：观感版初版有 3112 个独立网格（每扇窗、每条窗框、每台屋顶机组各一个对象），
三角形只有 4 万，几何量很小，但三千次绘制调用把 CPU 压垮，帧率掉到个位数。
`src/core/merge_static.js` 按材质把静态几何烘焙进世界坐标后合并，
广场 3112 → 27 个网格，小区 1984 → 29 个，三角形数不变。

代价是合并后整块不再按视锥剔除（`frustumCulled = false`），
但只有二三十个对象，这个代价远小于三千次调用。

`pbr()` 有材质缓存：同参数只造一个实例，合并时才能把更多网格收进同一组。
调用方要改材质（勒脚调暗、压顶提亮）必须自己 `clone()`，不要原地改。

**设备跟随**：`Cinematic.set_follow(entity, {mode, eye_y})`，与轨道相机互斥。
第三人称机位在设备后上方（5.2 米 / 抬 2.2 米），第一人称按视高（狗 1.15 米、人形 1.62 米）。
观感版页面上 `1–9` 跟随设备、`G`/`Esc` 回全局、`空格` 开关右上角第一人称小窗。
默认机位是 3D 俯视（`VIEWS.campus` 的 `phi: 1.02`），总平面转 90° 对准 16:9，
用来代替 2D 指挥图；`G` 回到的就是这个机位。
小窗用第二个渲染器画同一棵场景，渲染时机身临时隐藏；主渲染器带后期管线，
在同一渲染器里用视口裁切画第二视角会破坏后期链。

**相机包围盒**：`cam_clamp` 由场景在 `root.userData.frame.cam_clamp` 里声明，
`Cinematic._loop()` 每帧把相机与目标点一起夹进去。地铁站厅是封闭盒子，
不加约束会退到盒子外看到天空。留 4 米余量，贴太近时近裁剪面会切掉半块墙。

**镜头交互**：拖拽用「本次事件 − 上次事件」的增量，不是「本次 − 按下点」的累计值。
早先用累计值时，又把结果叠加到上一次的角度上，拖得越快转得越狠，一冲一冲的。
角度与距离朝目标插值（阻尼按 60fps 校准），拖动期间直接同步，松手不跳。
指针事件挂在 window 上、只跳过 `<button>`，所以页面任意位置都能起手转视角。
按 R 或点右上角 ⟳ 复位。

**画质档位**：右上角 低 / 中 / 高，也可用 `?q=low|medium|high`。
三处最贵的是屏幕空间环境光遮蔽（每帧多渲深度、法线、AO 三张全屏图）、
像素比（2 倍等于四倍像素）与阴影贴图。默认按 CPU 核数与视口像素自动选，
medium 为默认：像素比 1.2、GTAO 8 采样、阴影 2048。页面上有实时帧率。

**演示加速**：`agents.json` 里的 `speed_mps` 是 10 与 8，真实机器狗约 1.6 m/s。这里是为了让调度在十几秒内完成，不是实测值。

**场景缓存**：`engine.ensureScene` 构建时捕获该场景新注册的 ticker，切走后不再执行，非活动场景不耗 CPU。

**实体接口**：`Dog` 与 `Humanoid` 提供同名接口（`position`、`heading`、`setFirstPerson`、`viewYaw`、`viewPitch`、`walkTo`、`stop`、`startScan` 等），调度与视角代码不区分类型。

**视高**：机器狗 1.15 m、视场角 72°；人形 1.62 m、视场角 68°。狗不抬视高会是蚂蚁视角，地面目标看不清。

**2D 底图**：由 `engine.snapshotTopDown` 从 3D 场景离屏渲染生成，与 3D 天然对齐，不单独维护一张平面图。

**道路**：不再是贴图，是独立几何体。白色边线（`roads.edge`）在 `y=0.06`，黑色沥青面（`roads.surface`）在 `y=0.14`，边线只露出外沿 0.3 米。两层必须拉开 8 厘米，否则远处俯视会 z-fighting 出黑白条纹。改颜色只动 `road_layer()` 里的 `line_mat` 与 `road_mat`。

**行道树**：点位由 Python 预计算（避开建筑、水面、林地、路面），前端用 `InstancedMesh` 绘制，211 棵树 + 71 丛灌木只占 4 次绘制调用。调密度改 `build_roads.py` 的 `TREE_STEP_M`。

**帧时间**：`dt` 上限 0.05 秒。低帧率时仿真会放慢而不是跳帧，避免机器狗瞬移穿过目标。

**帧率显示**：用墙钟时间统计，不用累计 `dt`，否则低帧率下数字虚高。

**地形**：`terrain.js` 按多边形生成高度场。高度 = 边界过渡 × 山脊钟形 × 分形噪声，山脚平滑归零。
巡检空地通过 `flatten` 参数压到 0，向四周 45 米缓坡过渡，否则地形会从空地底下顶起来。
**网格本体必须 `mesh.position.set(wc.x, 0, wc.z)`**：高度是按世界坐标算的，网格不挪位置，山会全堆到图幅原点。
同一处：`scatter_hill_trees` 撒点用的是网格局部坐标，落地时要补 `mesh.position` 偏移。

**小区布局**：数据在 `scene_extra.json`，由 `map_trace/newmap2/enrich_community.py` 生成。
轮廓是多边形时**几何内缩会甩尖刺或自交**，所以一律走栅格腐蚀（`erode_polygon`）：
环路按边界内缩 9 米，可建区按 20 米。楼栋从大到小贪心摆（36 × 12 的板楼先摆，
24 × 11 的小楼补缝隙），每一步都检查「四角与四边中点都在可建区内」且与已摆楼栋留够间距，
斜边的楔形区域也能填满。路面在前端用 `ribbon()` 加宽。

**小山**：`scene_campus.js` 里的 `SMALL_HILLS`。这个尺度下二十多米的小丘从六百米外
只剩一道浅影，四五十米才有山的轮廓，定高度时要按「一眼能不能看出来」来给，不能按实际地形图。

**站台高度**：地铁站台抬高 0.9 米，`build_scene` 返回 `floor_y`，`World.make_agent` 据此把设备放到台面上，
`FirstPersonRig` 也加了这个偏移。其他场景没有该字段，按 0 处理。

**列车**：两列车**对开**，0 号轨向东、1 号轨向西，相位差半个周期。
`train_x(u)` 决定位置：进站减速 35%、停站 `dwell_s/cycle_s`、出站加速余下；
停站时车组中心停在站厅中心 `cw.x`，反向车的位置以 `cw.x` 镜像、车头也转 180°。
动画走 `addTick`，被 engine 捕获为场景私有，切走后不再执行。

**路面与楼体的冲突**：建筑从旧图迁移、道路从新图标注，两套几何对不齐，
实测 28 栋楼压在路面上。路面是贴地几何，会从楼脚钻出来又消失，
看起来像楼和路互相穿模。处理办法是让路面让位：`fix_road_conflict.py` 把楼体下方
的路面挖掉（楼体外扩 1 米），并保留挖出的孔洞——用 `RETR_EXTERNAL` 会丢掉整栋楼落在
路面内部时形成的洞，等于没裁。

**站厅轨行区**：没有在地坪上挖洞，轨道带抬到地面之上 9 厘米，视觉上是「站台高、轨道低」。
要做真正的下沉槽，需要在站厅地坪多边形上开洞。

## 七、演示流程

1. 打开页面，默认进入校园场景，第一人称视角在第一台机器狗上。
2. 点顶栏「剧本 1」，校园教学楼东侧出现明火告警。

8. 点顶栏「轮播」进入无人值守模式，三个剧本自动循环，告警不再弹窗而是直接切视角。

## 九、移动端预警接收页（2026-11-09）

在原有观感版上加的伴随页面：手机扫码打开，实时看大屏的异常信息。

  的内存事件日志（最近 500 条）→ SSE → `src/mobile/store.js` 回放事件合并成卡片 → 手机 UI。
- 总线只在 dev server / preview 里存在，没有引入新进程；单文件离线包要实时接收需另起服务。
- 手机端功能：连接状态/未读角标/声音开关、场景条、四项统计、全部/待处置/处置中/已处置筛选、
  五段进度卡片、生命周期详情抽屉、新预警 toast + WebAudio 提示音 + 振动、刷新恢复、断线重连。
- 连不上总线时自动进入「演示模式」，用 `src/mobile/demo_feed.js` 按真实节奏模拟整条状态机，
  顶部有明确标注，不冒充真实数据。
- 事件契约见 `src/mobile/contract.js`，状态机只允许 phase 前进，乱序事件不会让卡片倒退。
- 大屏右上角「手机」按钮：向 `/api/alerts/info` 问本机局域网 IPv4，生成二维码；
  单文件 `file://` 下会先探本机 5179，探到就把事件发到那里的总线。

完整说明见 `../docs/07_移动预警接收页.md`；验收脚本 `_alert_bus_probe.mjs` 与 `_mobile_probe.mjs`。

## 十、四模型场景应用（2026-11-09）

展台的对外口径是「四个场景各一个专属模型」，代码里的唯一定义在
`src/mobile/contract.js` 的 `SCENE_MODELS`：

| 模型 | 场景 | 演示中接入的异常 |
| --- | --- | --- |
| 校园巡检模型 | 校园 | 明火、人员聚集、垃圾堆积 |
| 小区安防模型 | 小区 | 烟雾火灾、出入口拥挤、垃圾满溢 |
| 地铁客运模型 | 地铁 | 明火烟雾、人员密度异常、通道遗留物 |
| 森林火险模型 | 森林 | 火险烟雾、人员活动异常、林区垃圾 |

应用链路：模型识别 → 风险研判 → 就近调度 → 移动触达。

- 大屏：顶部模型条随页签切换；事件流/消息条带模型署名。
- 手机：卡片模型署名 + 置信度；详情有四模型 chips、应用链路、模型研判；
  顶栏「模型」打开四模型应用总览。
- 模型输出层：`incident.analysis = { confidence, detect, rationale, suggestion }`。
  真实模型接入前由 `default_analysis()` 生成模拟值，接入后覆盖同名字段即可。
- 演示模式：`src/mobile/demo_feed.js` 按 校园→小区→地铁→森林 轮换四个模型。

讲解话术、能力清单与真实/模拟边界见 `../docs/08_四大模型场景应用.md`；
验收脚本 `tools/checks/_model_bar_probe.mjs`（大屏）与 `tools/checks/_mobile_probe.mjs`（手机端模型展示）。
